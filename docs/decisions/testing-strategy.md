# Testing strategy by category

**Status:** Active (2026-09-30)

## Context
Perseus is a desktop app (Tauri + React) with a Rust core that talks to a third-party API (SoundCloud) and writes
files to the user's disk. There is no server, no SQL database, no login and no multi-user support. The standard list
of test categories (functional, UI, backend, database, performance, security, resilience, compatibility, data, code
techniques, operations, coverage) was applied to what actually exists: every category has a real test or a
documented reason why it does not apply, along with the equivalent that covers the same risk.

## Decision
A single orchestrator, `scripts/test-all.ps1` (`-Sanity` for a quick pass, the default, `-Full` for the heavy
stages, `-Offline`), with one log per stage in `target/test-reports/`. CI: `ci.yml` on every push (including E2E on 3
engines and secret scanning) and a weekly `quality.yml` (fuzzing, performance, mutation).

### 1. Functional correctness
| Category | Where |
|---|---|
| Unit | `#[test]` per module in the core/Tauri; Vitest in `web/src/**` |
| Integration | engine + client + wiremock; Tauri's `JobManager`; the CLI binary (`crates/perseus-cli/tests/cli.rs`) |
| Component | Vitest + Testing Library (`CommandBar`, `Settings`, `ReleaseView`, `SearchResults`, `Sidebar`) |
| API | IPC commands (Tauri tests); the SoundCloud API client against wiremock (status, payload, pagination, errors) |
| E2E | Playwright with a mocked IPC backend; a real end-to-end smoke test |
| Regression | tests named after their bugs: archive extension, template collision, archive traversal, URL history (v0.1) |
| Smoke | `scripts/smoke.ps1` (the release binary against the real SoundCloud) |
| Sanity | `test-all.ps1 -Sanity` |
| Acceptance | the rules in `business-rules.md` as tests (sync never deletes, numbering by position, anonymous, DRM refused) + smoke tests of user flows |
| Contract | `contracts/log-events.json` (generated by Rust; the frontend requires a translation in 11 languages) and `contracts/job-in.json` (sent by the frontend; Rust accepts it with `deny_unknown_fields`) |
| Snapshot/golden | the CLI `--help` (`tests/golden/help.txt`), exact `.m3u8` output, log events, visual baselines |

### 2. Frontend / UI
| Category | Where |
|---|---|
| UI and interaction | Vitest + `e2e/interaction.spec.ts` (click, keyboard, arrow keys, Enter) |
| Visual regression | `e2e/visual.spec.ts` (`toHaveScreenshot`, baseline on Chromium/Windows) |
| Cross-browser | Chromium, WebKit (Tauri's engine on Linux/macOS) and Firefox |
| Responsive | 6 viewports from 768 to 1920 px, with no horizontal overflow |
| Accessibility | axe (WCAG 2.1 AA) + keyboard-only navigation |
| Forms | settings limits; an empty field disables actions |
| Navigation | job history in the sidebar |
| i18n / l10n | 11 languages, CLDR plurals, numbers/dates through `Intl`, Arabic in RTL, the event contract |
| Offline | the full flow with no external requests (privacy); downloads need the network by nature |

### 3. Backend / IPC
| Category | Where / why |
|---|---|
| Endpoint | every IPC command and every SoundCloud API endpoint used |
| Authentication | N/A for users (an anonymous product). Equivalent: discovery, caching and a single renewal of the public `client_id` on 401 |
| Authorization | minimal IPC capabilities (event listening only), tested; `open_folder` only opens a folder registered by the job |
| Validation | `JobIn` with limits, unknown fields rejected; hostile URLs; properties |
| Error handling | mapping status codes to domain errors; CLI exit codes |
| Concurrency | two jobs in the same folder; API request peak <= 8; job limits |
| Idempotency | a re-sync downloads nothing; a template change reuses files through the archive |
| Rate limiting | 429 with `Retry-After`; the bandwidth limiter; the API semaphore |
| Webhooks | N/A: there are no webhooks |

### 4. Database
There is no database. Persistence is `.perseus-archive.json` (per folder) and `library.json` (global), and they get
the equivalent tests: CRUD (round trips), constraints (plain file names only), transactions (`atomic_write` keeps the
previous content on failure), migration/compatibility (files without a version and from a future version),
integrity (entries for missing files dropped), concurrency (simultaneous writers merged), backup/restore (a lost
archive rebuilt from the files). N/A: SQL, database deadlocks, replication, query performance.

### 5. Performance (`-Full`, release build)
Load (500 tracks with injected 503s), spikes (120 x 503), soak (60 runs + memory), volume (5,000 tracks in 100
batches), scalability (1/4/8/16 workers, requires >= 6x), capacity (worker and API limits), latency and throughput
(tracks/s and MB/s in the log), resources (a counting allocator for leaks; a disk space check).

Reference measurements (2026-09-30, release build, Windows 11, local simulated server; hardware figures, not an
SLA):

| Test | Result |
|---|---|
| Load | 500 tracks in 5.3 s (8.3 MB/s), 40 x 503 absorbed, a re-sync with no downloads |
| Scalability (150 ms latency per track) | 1 worker 4.9 tracks/s; 4 → 20.4; 8 → 39.7; 16 → 70.8 (14.6x) |
| Spike | 120 x 503 absorbed in 17.7 s (104 by transport retries, 16 by track retries), 200/200 tracks |
| Soak | 60 runs: stable timing (61 ms → 39 ms); live memory 2.2 MB → 2.7 MB (test limit: +2 MB) |
| Volume | 5,000 tracks hydrated in 100 batches in 0.37 s, peaking at 8 concurrent API requests |

Mutation (2026-09-30): Rust had 188 viable mutants and 7 survivors before the new tests; after them, 2 equivalent
mutants remain (`filesystem.rs` truncation `>`/`>=` and `transcoding.rs` `rank` `-`/`/`, which preserve the result).
Frontend (Stryker, `lib` and `i18n`): 77.9% → 93.4% after targeted tests (`api.ts` 100%, `format.ts` 97%,
`locales.ts` 91%, `describe.ts` 88%, `translate.ts` 88%).

### 6. Security
| Category | Where / why |
|---|---|
| Input validation | hostile URLs (CLI DAST), properties, host allowlist, `ensure_within` |
| Path traversal / spoofing | tampered archives, templates, C0/C1 controls and bidi (U+202E) stripped from names |
| XSS | titles containing HTML rendered as text (Vitest and E2E) |
| Secrets | `scripts/scan-secrets.mjs` + a test that the `client_id` never appears in logs |
| Dependencies | cargo-deny (RustSec, licenses, sources), npm audit |
| SAST | pedantic clippy, strict ESLint, CodeQL (Rust and TS) in CI |
| DAST | a hostile-input harness against the binary; there is no network surface (no server) |
| Configuration | CSP without `unsafe-*`, `connect-src` limited to IPC, per-user installer, versions in sync |
| N/A | SQL injection (no SQL), CSRF and sessions (no server, no cookies), containers (no image) |
| Pentest | outside automated scope; recommended manually before distributing at scale |

### 7. Resilience
Fault injection and chaos (`RawServer` cuts the body mid-stream; random 5xx), network drops with `Range` resume,
corrupted `.part` files discarded, timeouts/cancellation of stalled transfers, transport and track retries,
dependency failures (an isolated API batch, a fatal resolution error), recovery (a lost archive). Circuit breaker:
the equivalent is Watch mode's progressive backoff (tested). N/A: server failover and disaster recovery (a local
app; Perseus never deletes user files).

### 8. Compatibility
Chromium/WebKit/Firefox engines; Windows (CI and local), Linux (frontend/E2E CI). macOS and mobile: N/A (no build).
Backward compatibility: old settings in `localStorage`, archives without a version. Forward compatibility: archives
from a newer major version with extra fields. SoundCloud API: live tests and smoke tests detect breakage.

### 9. Data
Audio validation (header, size, duration), byte-for-byte integrity after resume and with concurrent jobs, tags
written and read back, quality (track deduplication, stub hydration), reconciliation (sync against the playlist; the
library against the disk). N/A: ETL.

### 10. Code techniques
Mutation (cargo-mutants on rule and security modules; Stryker on `web/src/lib` and `i18n`), generative fuzzing
(proptest, 20,000 cases; libFuzzer requires nightly), properties (18), static analysis and types (clippy, strict
tsc), memory leaks (soak with the counting allocator), races (concurrent tests; `unsafe` forbidden outside the test
allocator). Loom: N/A (no custom synchronization primitives beyond `Mutex`).

### 11. Operations
Health/readiness/liveness/alerts: N/A (a desktop app, not a service). Equivalents: a startup failure dialog, single
instance, configuration tests (CSP, capabilities, versions), the installer build with a PE check in the smoke test,
observability (JSON logs with `run_id`, no secrets). Rollback: earlier releases stay on GitHub (no auto-update).

### 12. Coverage and quality
Lines/regions/functions in Rust (`cargo llvm-cov`, at least 80% of lines); lines/functions/branches in the frontend
(v8). Branch coverage in Rust requires nightly (N/A). Mutation score, pass rate, flakiness (repeated runs in
`-Full`) and time per stage in `summary.txt`.

## Consequences
- The default suite stays fast enough for every push; the heavy work runs weekly.
- N/A categories become an explicit decision rather than an oversight: if a server, a database or login ever
  appears, this strategy has to be revisited.
- Build artifacts grow with the suites; the orchestrator disables the incremental cache, cleans instrumented
  coverage builds and aborts below 15 GB of free space.
